# เทสต์ตาม Workflow

วงจรของกล่อง

```
ลงทะเบียน ──> pending ──ติดป้าย──> putaway ──> warehouse ──ส่งออก──> out
                                                ▲   │                 │
                                                │   ├─พัก──> hold     ├─ไม่กลับ──> lost
                                      ปลด/เก็บใหม่ │   └─ชำรุด─> damage  │
                                                └──────── รับคืน ◄─────┘
```

ช่องทางที่เปลี่ยนสถานะได้

| ช่องทาง | เส้นทางในระบบ |
|---|---|
| หน้าเว็บ (ยิงมือ, Excel) | `PUT /api/state` ส่งข้อมูลทั้งก้อน |
| PDA | `/api/boxes/*`, `/api/gate/in`, `/api/gate/out` |
| RFID เครื่องประจำประตู | `/api/rfid/fx9600/:gate/webhook` |
| กล้องป้ายทะเบียน | `/api/gate/lpr` |
| ตรวจนับ | `/api/cycle-counts/*` |

ประตูในเทสต์: 1 = ขาเข้า, 2 = ขาออก, 3 = สองทาง (ยืนยันบนจอ), 4 = สองทาง (เสาอากาศบอกทิศ), 9 = คลังที่สอง

## Workflow ที่ทดสอบ

| รหัส | เรื่อง | ขั้นตอน |
|---|---|---|
| W1 | วงจรปกติ | ลงทะเบียน → ติดป้าย → เก็บ → ส่ง → คืน, ทำข้ามขั้น, ทำซ้ำ, บาร์โค้ดซ้ำ, ชุดที่มีกล่องเสียปน |
| W2 | PDA | ผู้สแกน, สแกน RFID กับบาร์โค้ดกล่องเดียว, พนักงานพ้นสภาพ, ประตูไม่มีจริง, รหัสไม่รู้จัก, ทิศประตู |
| W3 | มีปัญหา | คืนแบบชำรุด → ปลด → ส่งใหม่, พัก/ชำรุดผ่านประตูเข้า, พักกล่องที่ออกไปแล้ว, กล่องหายกลับมา |
| W4 | ย้ายคลัง | ส่งจากคลังหนึ่ง รับอีกคลัง แล้วส่งจากคลังใหม่ |
| W5 | RFID | ประตูทางเดียว, ยังไม่เลือกลูกค้า, ประตูยืนยันบนจอ, เสาอากาศสองต้น, ข้ามคลัง, กล่องชำรุด/พัก |
| W6 | RFID + LPR | ป้ายตรง/ไม่ตรง, ความมั่นใจต่ำ |
| W7 | ตรวจนับ | ของหาย, ปิดรอบ, ตีเป็นสูญหาย |
| W8 | เว็บกับ PDA พร้อมกัน | หน้าเว็บที่ข้อมูลเก่ากดบันทึก หลัง PDA ทำรายการ |
| W9 | ข้อมูลหลัก | ลูกค้า/ประเภทกล่องที่ลบแล้ว, เลข DO ซ้ำ |
| W10 | ชนกันในเสี้ยววินาที | สองประตูสแกนกล่องเดียวพร้อมกัน |
| W11 | กฎเดียวกันตอนหน้าเว็บบันทึก | ส่ง/รับปกติ, ข้อมูลเก่า, ลบกล่อง, ผิดทิศประตู, กล่องพัก, DO ซ้ำ, กู้คืนข้อมูลสำรอง |

## วิธีรัน

```bash
cd backend && npx vitest run tests/workflows
```

W10 ต้องใช้ Postgres จริงแบบใช้แล้วทิ้ง (ห้ามชี้ไปฐานข้อมูลที่มีข้อมูล):

```bash
cd backend && RACE_DB=postgres://user:pass@localhost:5433/race npx vitest run tests/workflows/race
```

ข้อจำกัด

- การกันชนกันทำในตัวโปรแกรม ใช้ได้เมื่อรัน backend ตัวเดียว (แบบที่ติดตั้งอยู่)
- การกันข้อมูลเก่าทับครอบคลุมความเคลื่อนไหวของกล่อง การแก้ข้อมูลหลักหรือพนักงานจากสองหน้าจอพร้อมกันยังเป็นแบบบันทึกทีหลังชนะ

## ยังไม่ครอบคลุม

- หน้าจอจริงของเว็บและแอป PDA (เทสต์นี้ยิงที่เซิร์ฟเวอร์)
- PDA บันทึกออฟไลน์แล้วส่งย้อนหลัง
- นำเข้า Excel, สำรองและกู้คืนข้อมูล
- เครื่อง RFID, กล้อง และ Android จริง
